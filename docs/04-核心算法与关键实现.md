# 04 · 核心算法与关键实现

> 版本 v1.0 ｜ 2026-11-26 ｜ 对应阶段：核心功能开发

## 1. 时间冲突检测（src/utils/conflict.ts）

### 判定规则

两门课冲突，当且仅当：

1. **同一学期**（不同学期的课不会同时上）；
2. 存在一对时间段，满足：**同一天** 且 **节次区间重叠**（闭区间：`a.start <= b.end && b.start <= a.end`）且 **周次有交集**（任意公共周）。

```ts
export function slotsConflict(a: CourseSlot, b: CourseSlot): boolean {
  return a.day === b.day && periodsOverlap(a.start, a.end, b.start, b.end) && weeksOverlap(a.weeks, b.weeks)
}
```

单门课可能有多个时间段（如周一 3-4 节 + 周三 1-2 节），两门课两两时间段配对检查即可。加入课表前对新课程与全部已选课程做 `findConflict`，命中即拦截并返回冲突课程名。

### 复杂度

每门课时间段数 m 很小（≤5），对 n 门已选课为 O(n·m²)，n=30 时毫秒级，无需优化。

## 2. 课表重叠块的泳道布局（TimetableGrid.vue）

当已选数据中确实存在重叠时（兜底展示），需要把重叠块并排渲染而不是互相遮挡：

1. 按天分组，块按 `起始节次` 排序；
2. **切分连通分量**：扫描排序后的块，若与当前分量中任一块的结束节次 `>= 下一块的起始节次`，则并入分量（传递重叠：A 与 B 重叠、B 与 C 重叠 → A、B、C 同分量）；
3. **贪心分配泳道**：维护每条泳道的"最后占用结束节次"，把每块放入第一条空闲泳道；泳道总数即分量宽度，所有块等宽均分当天列宽；
4. 渲染时 `left = day × 20% + lane × (20% / lanes)`，`top = (start-1) × 48px`，块高 = 节数 × 48px。

## 3. 学分统计（src/utils/credit.ts）

- 所有求和用 `round1()`（`Math.round(n*10)/10`）保留一位小数，避免 `0.1+0.2` 类浮点误差；
- `creditsByCategory`：按六类汇总；`creditsPerSemester`：按学期汇总并升序；
- 差距 = `max(0, 要求 - 已得)`；类别达标 = `已得 >= 要求`；总达标且各类达标时显示"完成"横幅。

## 4. 前置课程检查（src/utils/conflict.ts）

- `prerequisitesSatisfied(course, selected)`：课程的全部前置 id 都在已选列表 → 满足；
- `missingPrerequisites(selected, catalog)`：反向扫描已选课程，找出每门课缺失的前置课程（从课程库解析名称），供规划页提醒列表使用；
- 设计决策：**前置缺失只提醒、不拦截**（学生可以跨学期预选或走免修流程），而**时间冲突与学分超限直接拦截**（硬约束）。

## 5. 表单校验（CustomCourseForm.vue）

- **字段级**：`validateField(field)` 纯函数返回错误文案——必填、名称长度 2-30、学分 0.5-10 且为 0.5 倍数、学时 1-400 整数、节次 / 周次非空；
- **跨字段**：结束节次 ≥ 起始节次、结束周 ≥ 起始周；
- **展示门控**：错误仅当 `touched[field] || submitted` 时显示，避免一进页面满屏红字；提交时统一标记全部 touched；
- **业务级**：字段校验通过后，用同一套 `findConflict` / `exceedsCreditCap` 做冲突与学分上限校验，失败写入全局错误区并中断提交。

## 6. 持久化与数据流

```
用户操作 → Pinia action（校验 → 变更 selected）
        → persist()（JSON 序列化 → localStorage）
启动时   → loadJSON（解析失败降级为空数组）→ 初始化 selected
```

全部页面通过 store 共享同一份数据：课表网格、规划页进度、头部学分徽章在任一页面变更后即时同步（Vue 响应式 + Pinia 单一数据源）。
